# หารดี

เว็บแบ่งบิลตามรายการ เลือกได้ว่าแต่ละรายการใครหารบ้าง จะหารเท่า หารตามสัดส่วน หรือใส่ยอดเองก็ได้ ทำด้วย Next.js (App Router), React, TypeScript (strict) และ Supabase

ไม่ต้องล็อกอินก็ใช้ได้ (โหมด Guest)

## รันในเครื่อง

ใช้ Node.js ตามที่ระบุใน `engines` ของ `package.json` ตัวที่ใช้พัฒนาคือ 24.19.0

```powershell
cd C:\Users\krail\OneDrive\Desktop\web02
npm.cmd ci
npm.cmd run dev
```

เปิด http://localhost:3000 แล้วกด "ลองบิลตัวอย่าง" หรือสร้างบิลเองเลย

> บน Windows ใช้ `npm.cmd` แทน `npm` เพราะ execution policy ของ PowerShell มักบล็อก `npm.ps1`

## ทำอะไรได้บ้าง

### Guest

- เพิ่มคนได้ 4 คน เลือกคนหารทีละรายการ
- ตั้งค่าบริการ, VAT, ส่วนลด และดูยอดรายคนพร้อมรายละเอียด
- ดาวน์โหลดสรุปเป็น PNG (มีลายน้ำ) และแชร์ผ่าน Web Share ถ้าเบราว์เซอร์รองรับ
- บิลถูกเก็บใน localStorage อัตโนมัติ รวมถึงบิลที่กรอกยังไม่ครบ มีประวัติ ค้นหาตามชื่อ กรองตามวันที่ และสำรอง/นำเข้าเป็น JSON ได้

ข้อมูล Guest อยู่ในเบราว์เซอร์เท่านั้น ถ้าล้างข้อมูลเบราว์เซอร์บิลจะหาย แนะนำให้สำรองเป็นระยะ

### สมาชิก

เข้าสู่ระบบด้วย magic link หรือ Google แล้วจะได้เพิ่มเติม:

- เพิ่มคนได้เกิน 4 คน
- บันทึกบิลเข้าบัญชี ดูประวัติบนคลาวด์
- รายชื่อเพื่อน และผู้จ่ายหน้าร้าน
- สถานะโอนเงิน และ QR พร้อมเพย์
- ลิงก์แชร์แบบอ่านอย่างเดียว เพิกถอนได้
- ภาพสรุปแบบไม่มีลายน้ำ

ตอนล็อกอินเว็บจะถามว่าจะย้ายบิล Guest ที่คำนวณได้แล้วเข้าบัญชีไหม ข้อมูลในเครื่องไม่ถูกลบ บิลที่กรอกไม่ครบต้องแก้ให้เสร็จก่อนถึงจะย้ายได้

### อื่น ๆ

- เทมเพลตมื้ออาหาร / ปิ้งย่าง / ทริป
- ธีมมืด
- สรุปรายเดือน ดูยอดค้าง
- คำนวณยอดสุทธิเพื่อลดจำนวนครั้งที่ต้องโอน โดยใช้เพื่อนที่บันทึกไว้เป็นตัวเชื่อมคนข้ามบิล

สถานะ "โอนแล้ว" คือการกดทำเครื่องหมายเอง ระบบไม่ได้ตรวจกับรายการธนาคาร ส่วน QR ใช้เลขพร้อมเพย์ในโปรไฟล์ ต้องตั้งให้ตรงกับผู้จ่ายหน้าร้าน และควรเช็กชื่อผู้รับในแอปธนาคารก่อนโอนทุกครั้ง

## ตั้งค่า Supabase

จำเป็นเฉพาะถ้าจะเปิดระบบสมาชิก ถ้าใช้แค่ Guest ข้ามส่วนนี้ได้

1. สร้างโปรเจกต์ใน Supabase แล้วคัดลอก Project URL กับ publishable key จากแดชบอร์ด
2. คัดลอก `.env.example` เป็น `.env.local` แล้วกรอก

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   ```

   ใส่ได้เฉพาะ publishable key อย่าใส่ service-role/secret key ในตัวแปร `NEXT_PUBLIC_*` และอย่า commit `.env.local`

3. เปิด SQL Editor แล้วรัน `supabase/migrations/202610180001_initial.sql` ไฟล์นี้สร้างตาราง, RLS, RPC และ index รวมถึงเพิ่ม `bills` เข้า `supabase_realtime` (ถ้ามี publication นี้อยู่) และใช้ `pgcrypto` ใน schema `extensions` ตามค่าปกติของ Supabase
4. ที่ Authentication ตั้ง Site URL เป็น `http://localhost:3000` และเพิ่ม `http://localhost:3000/auth/callback` ใน Redirect URLs ตอนขึ้นเซิร์ฟเวอร์จริงให้เพิ่ม URL ของเว็บจริงด้วย
5. เปิด Email provider สำหรับ magic link เว็บใช้ PKCE แลก code ที่ `/auth/callback` ดังนั้นต้องเปิดลิงก์ในเบราว์เซอร์เดียวกับที่กดขอเข้าสู่ระบบ
6. ถ้าจะใช้ Google ให้เปิด Google provider ใน Supabase ใส่ OAuth client ID/secret แล้วไปตั้ง Authorized redirect URI ใน Google Cloud ให้ตรงกับ callback ที่ Supabase Dashboard แสดงไว้ จากนั้นอนุญาต callback ของแอปตามข้อ 4
7. รีสตาร์ตเซิร์ฟเวอร์หลังแก้ env ถ้ารัน production ต้อง build ใหม่ด้วย เพราะ `NEXT_PUBLIC_*` ถูกฝังใน client bundle

### ข้อมูลตัวอย่าง

สมัคร/ล็อกอินบัญชีทดสอบก่อน แล้วคัดลอก UUID จาก Authentication > Users ไปแทน `REPLACE_WITH_AUTH_USER_UUID` ใน `supabase/seed.sql` จากนั้นรันใน SQL Editor รันทุกครั้งจะได้บิลตัวอย่างเพิ่มหนึ่งบิล และไม่มีการตั้งเลขพร้อมเพย์จริงให้

## สูตรคำนวณและการปัดเศษ

ตัวคำนวณอยู่ที่ `src/lib/split/` เป็น pure function ทั้งหมด ใช้ `bigint` หน่วยสตางค์ตลอด ส่งผ่าน JSON เป็นสตริงทศนิยม และเก็บในฐานข้อมูลเป็น `bigint` สตางค์

**ข้อจำกัดของค่าที่กรอก**

- จำนวนเงิน: ทศนิยมไม่เกิน 2 ตำแหน่ง สูงสุด 999,999,999.99 บาทต่อช่อง
- น้ำหนัก (ตอนหารตามสัดส่วน): ต้องมากกว่า 0 ทศนิยมได้ 6 ตำแหน่ง
- เปอร์เซ็นต์: 0–100 ทศนิยมได้ 2 ตำแหน่ง
- กรอกเกินจากนี้จะขึ้น error

**การปัดเศษ**

ใช้ Largest Remainder เพื่อให้ผลรวมตรงทุกสตางค์ ถ้าเศษเท่ากัน คนจะเรียงตามลำดับที่เพิ่มเข้าบิล ส่วนรายการเรียงตามลำดับที่แสดง

**ค่าบริการ / VAT / ส่วนลด**

- ค่าบริการคิดจากราคารวมแล้วปัด half-up ที่ระดับบิล จากนั้นกระจายตามราคารายการ และตามส่วนแบ่งของแต่ละคนในรายการ
- ราคา**ไม่รวม VAT**: VAT คิดจาก (ราคา + ค่าบริการ) เช่น 100 + service 10% + VAT 7% = 117.70 บาท
- ราคา**รวม VAT แล้ว**: ไม่บวก VAT ซ้ำบนราคาอาหาร แต่ยังคิด VAT บนค่าบริการ เช่น 100 + service 10% + VAT 7% = 110.70 บาท ตัวเลข VAT ที่แสดงในกรณีนี้เป็นข้อมูลประกอบ
- ส่วนลดหักหลังค่าบริการและ VAT โดยกระจายตามยอดก่อนลดของแต่ละคน และห้ามเกินยอดบิล

**โหมดระบุยอดเอง**

ยอดที่ใส่ต้องรวมเท่ากับราคารายการ ถ้าไม่เท่าจะแสดงส่วนต่างให้เห็น รายการที่ไม่มีคนหารจะขึ้น error ให้ไปแก้

**การลดจำนวนครั้งที่โอน**

ใช้ greedy settlement แบบ deterministic ช่วยลดจำนวนการโอนได้ แต่ไม่รับประกันว่าน้อยที่สุดในทุกกรณี

รายละเอียดเพิ่มเติมอยู่ใน `docs/`

## ฐานข้อมูลและการบันทึก

ตารางหลัก:

- `profiles` โปรไฟล์และพร้อมเพย์
- `friends` เพื่อน
- `bills` เจ้าของบิล วันที่ ค่าบริการ ภาษี JSON สำหรับแก้ไข และ hash ของลิงก์แชร์
- `people`, `items` รายการลูกของบิล
- `item_participants` เชื่อมคนกับรายการ
- `payments` สถานะการโอน

`item_participants` เป็น many-to-many เพราะหนึ่งรายการมีหลายคนหาร และคนหนึ่งคนหารได้หลายรายการ โดยแต่ละคู่มีน้ำหนักหรือยอดของตัวเอง

**สิทธิ์การเข้าถึง**

เปิด RLS ครบทั้ง 7 ตาราง ผูกสิทธิ์เจ้าของด้วย `auth.uid()` และตรวจผ่านบิลแม่ ไม่มีตารางไหนเปิดอ่านแบบสาธารณะ

ลิงก์แชร์ใช้ token สุ่ม 256 บิต เก็บเฉพาะ SHA-256 hash ในฐานข้อมูล และอ่านผ่าน security-definer RPC ที่คืนเฉพาะข้อมูลสรุปกับเลขพร้อมเพย์ ใครมีลิงก์ก็อ่านข้อมูลชุดนี้ได้จนกว่าเจ้าของจะเพิกถอน

**การบันทึก**

- `save_bill` ทำงานเป็น transaction เดียว ปรับทั้ง JSON และตารางลูกพร้อมกัน
- API ตรวจข้อมูลด้วย Zod และคำนวณซ้ำฝั่ง server
- ใช้ `expectedUpdatedAt` ตรวจเวอร์ชัน ถ้าอีกหน้าต่างแก้ไปก่อนจะตอบ 409 กันการเขียนทับโดยไม่รู้ตัว
- Realtime จะแจ้งให้เปิดฉบับล่าสุด แต่ยังไม่มีการ merge การแก้ที่ขัดกันให้อัตโนมัติ
- Guest บันทึกในเครื่องอัตโนมัติ ส่วนสมาชิกต้องกดบันทึกเข้าบัญชีเองหลังแก้
- ก่อนสร้างลิงก์แชร์หรือเปลี่ยนสถานะโอน เว็บจะบันทึกฉบับที่แก้ค้างอยู่ก่อน
- การเปลี่ยนสถานะโอนจะแสดงผลทันที และย้อนกลับเป็นค่าเดิมถ้า server ตอบไม่สำเร็จ

## ทดสอบ

```powershell
npm.cmd run check
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

- `check` รวม TypeScript, ESLint และ Vitest (unit/property tests, validation, storage, PromptPay payload, PostgreSQL/RLS)
- `npm.cmd run test:rls` รันเฉพาะชุดทดสอบฐานข้อมูล ใช้ PGlite (PostgreSQL จริง) จำลอง auth schema และ roles ไม่ต้องมี Supabase credentials ครอบคลุมผู้ใช้ A/B, ตารางลูก, RPC, ลิงก์แชร์, stale save, การลบเพื่อน และ seed
- E2E เปิด production server เองที่พอร์ต 3000 ทดสอบการคำนวณ บันทึก/เรียกประวัติ ข้อจำกัด Guest โหมดระบุยอด การลบคน PNG หน้าจอเดสก์ท็อปและมือถือ ธีมมืด offline และลิงก์ที่ไม่ถูกต้อง

**ที่ยังไม่ได้ทดสอบ**

- การล็อกอินจริง, การส่งอีเมล, Google OAuth และ Realtime บน Supabase hosted ต้องลองกับโปรเจกต์ที่ตั้งค่าแล้ว ยังไม่เคยทดสอบกับบัญชีจริงบนเครื่องนี้
- PromptPay ทดสอบแค่ payload/CRC และการคิดยอดเป็นจำนวนเต็ม ยังไม่เคยสแกนด้วยแอปธนาคารจริง

## Production และ PWA

```powershell
npm.cmd run build
npm.cmd run start
```

Service worker ลงทะเบียนเฉพาะโหมด production และหลังจากเปิดเว็บแบบออนไลน์ครั้งแรกจนตัว worker พร้อม หลังจากนั้น Guest ถึงจะใช้แบบ offline ได้ การติดตั้ง PWA และ Web Share ต้องใช้เบราว์เซอร์ที่รองรับและต้องเป็น secure context (HTTPS หรือ localhost) ส่วนระบบสมาชิกกับลิงก์แชร์ต้องต่ออินเทอร์เน็ต

ตอน deploy:

1. ตั้ง env ทั้งสามตัว โดยให้ `NEXT_PUBLIC_SITE_URL` เป็น origin ของเว็บจริง
2. เพิ่ม callback URL ของเว็บจริงใน Supabase Auth
3. จึงค่อย build (เพราะค่า `NEXT_PUBLIC_*` ถูกฝังตอน build)

`.env.local` ใช้เฉพาะเครื่องพัฒนา
