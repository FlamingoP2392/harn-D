# การกระจายส่วนแบ่งด้วย Largest Remainder

ฟังก์ชันนี้เขียนเสร็จแล้วใน src/lib/split/allocate.ts เอกสารนี้เป็นข้อมูลอ้างอิงของ implementation

allocate รับ totalSatang เป็น bigint ไม่ติดลบ และ participants ที่มี personId ไม่ว่าง/ไม่ซ้ำ พร้อม weight เป็น bigint มากกว่า 0 คืน amountSatang ตามลำดับคนเดิม โดยไม่แก้ input

1. รวม weight ทั้งหมด
2. คำนวณโควตาของแต่ละคนด้วย totalSatang × weight หารผลรวมน้ำหนัก เก็บผลหารจำนวนเต็มและเศษ
3. นำยอดที่ยังแจกไม่ครบไปเพิ่มทีละ 1 สตางค์ตามเศษมากไปน้อย หากเศษเท่ากันให้ลำดับเดิมก่อน
4. คืนผลตามลำดับ input ผลรวมจึงตรงกับ totalSatang เสมอ

| ยอดสตางค์ | น้ำหนักตามลำดับ | ส่วนแบ่งสตางค์ |
| --- | --- | --- |
| 10,000 | 1, 1, 1 | 3,334 / 3,333 / 3,333 |
| 1 | 1, 1, 1 | 1 / 0 / 0 |
| 2 | 1, 1, 1 | 1 / 1 / 0 |
| 0 | 1, 1, 1 | 0 / 0 / 0 |
| 10,000 | 1, 2, 3 | 1,667 / 3,333 / 5,000 |
| 10,000 | 1,250,000 / 2,500,000 | 3,333 / 6,667 |

แกนนี้ไม่ import React, Next.js หรือ Supabase จึงใช้ร่วมกันบน client/server ได้ ผู้เรียกแปลงข้อความทศนิยมที่ตรวจ Zod แล้วเป็นจำนวนเต็มตามสเกล น้ำหนักใช้สเกล 6 ตำแหน่ง เปอร์เซ็นต์ใช้ basis points

calculateBill จัดลำดับผู้ร่วมหารตามลำดับคนในบิลก่อนเรียก allocate ไม่ใช้ลำดับการติ๊กชื่อเป็นตัวตัดสินเศษ ค่าบริการ ภาษี และส่วนลดใช้วิธีกระจายเดียวกันบนฐานยอดที่สัมพันธ์กัน

ตรวจด้วย npm.cmd run test:allocate หรือ npm.cmd run check มี unit cases และ property tests สำหรับผลรวม ไม่ติดลบ deterministic ไม่แก้ input และขอบเขตโควตา
